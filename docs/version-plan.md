# RPGshower 版本实施计划

更新日期：2026-09-15

## 版本规则

RPGshower 使用两套版本号：

- 应用版本：写在 `package.json`，描述网页功能和代码发布阶段，遵循 SemVer。
- 角色 JSON 版本：写在角色数据的 `schemaVersion`，描述 JSON 字段契约和迁移规则。

两者不要求同步变化。例如新增网页编辑能力可以只提升应用版本；只有改变角色 JSON 的必填字段、字段含义或兼容行为时，才需要提升 JSON 版本并提供迁移逻辑。

预发布阶段的含义：

- `alpha`：功能正在形成，数据或交互仍可能调整，不保证完整闭环。
- `beta`：核心闭环已经可用，正在补错误处理、测试和可用性。
- `rc`：功能范围冻结，只修复阻塞发布的问题。
- 无后缀版本：该阶段完成验收，可作为稳定版本使用。

## 当前版本

当前应用版本：`0.2.0-alpha.1`

当前角色 JSON 版本：`0.1.0`

当前阶段是 v1 的首个 alpha 迭代。v0 稳定版能力保持可用，并新增浏览器本地角色资料库基础操作；专用条目表单、搜索筛选和批量操作仍在计划中。

## 版本路线

### `0.1.0-alpha.1`：静态角色卡

目标：验证 React 页面、角色数据对象和组件拆分。

已完成：

- Vite、React、TypeScript 项目初始化。
- RPGshower 应用外壳和响应式布局。
- 示例角色数据。
- 角色卡静态展示。
- 角色头部、资源、属性、装备、技能组件拆分。

验收：能够启动开发服务器并看到由示例数据驱动的角色卡，生产构建通过。

### `0.1.0-beta.0`：可编辑的单角色工作台

目标：让用户能够在网页中修改常用字段，并通过 JSON 文件保存和恢复角色。

已完成：

- React state 和基础表单。
- JSON 文件导入和导出。
- Zod 运行时校验。
- 导入失败保留最后一份合法角色。

验收：用户可以编辑常用字段、导出文件、再次导入，并且非法 JSON 不会破坏当前角色。

### `0.1.0-beta.1`：完整 v0 数据闭环

目标：让单角色工作台覆盖角色卡、档案和完整 JSON 数据。

已完成：

- `archive`、`extensions` 和 `0.1.0` 兼容策略。
- 角色卡 / 档案视图切换。
- 完整 JSON 编辑器。
- 数据操作模块拆分。
- JSON 语法和 Schema 错误分类。
- 资源值非负及上下限约束。
- 15 项自动测试和项目文档。

验收已完成：

- 桌面端和移动端浏览器回归。
- 空列表、长文本和窄屏状态检查。
- v0 状态文档和发布候选版本同步。

### `0.1.0-rc.1`：v0 发布候选

进入条件：`0.1.0-beta.1` 的剩余验收全部通过。

计划：

- 冻结 v0 数据字段和交互范围。
- 只修复回归测试发现的问题。
- 补齐用户操作文档和发布说明。
- 确认导入、编辑、预览、导出、再导入闭环。

验收：桌面端和移动端均可完成完整闭环；所有自动检查通过；无阻塞性错误。

### `0.1.0`：v0 稳定版，单角色工作台

目标：发布第一个稳定版本。已于 2026-09-15 完成验收。

范围：

- 单角色角色卡和档案展示。
- 基础表单和完整 JSON 编辑。
- JSON 文件导入导出。
- `schemaVersion: "0.1.0"` 数据校验和兼容规则。
- 资源约束、错误恢复和回归测试。

明确不包含：多角色资料库、自动保存、账号、后端、规则计算、多人协作、AI 和媒体管理。

### `0.2.0`：v1，本地角色资料库

目标：从单角色工作台升级为可长期使用的本地创作工具。

当前进度：基础资料库迭代已开始。已实现浏览器本地存储、角色切换、新建、复制、删除、归档和恢复；专用条目表单、搜索筛选和批量操作仍待后续迭代。

实施顺序：

1. 抽离角色存储接口，先实现浏览器本地存储。
2. 增加创建、复制、删除、归档和恢复角色。
3. 增加角色列表、搜索、筛选、排序和批量导入导出。
4. 增加档案、标签、资源、属性、装备和技能的专用表单编辑。
5. 增加撤销、恢复示例、未保存提示和打印友好的导出。
6. 增加主题和只读分享预览。

验收：用户不编写 JSON 也能在一个设备上保存和管理多个完整角色，刷新后数据不丢失。

### `0.3.0`：v2，世界观项目和规则扩展

目标：管理一组互相关联的角色和世界设定。

实施顺序：

1. 增加项目、战役、世界、组织、阵营、地点和事件模型。
2. 建立角色与组织、地点、事件之间的关系。
3. 增加关系图、时间线和基础世界观导航。
4. 定义规则模板和扩展字段接口。
5. 增加派生属性、资源公式和可选规则适配包。
6. 增加数据迁移工具和稳定的公开 JSON Schema。

验收：一个项目可以容纳多类设定，切换规则模板不会破坏通用角色资料。

### `1.0.0`：v3，云端协作与开放生态

目标：让角色、战役和世界观资料能够安全地跨设备共享和协作。

实施顺序：

1. 增加账号、云端存储和跨设备同步。
2. 增加所有者、编辑者、只读访客权限。
3. 增加版本历史、差异比较、评论和协作编辑。
4. 增加公开或受限的分享链接、主持人视图和隐藏信息。
5. 发布 API、插件接口和第三方格式转换工具。
6. 再评估跑团会话、媒体管理、可视化和 AI 辅助功能的优先级。

验收：多个用户可以可靠地共享、编辑和恢复角色、战役与世界观数据，外部工具可以通过 API 或插件接入。

## 每个版本的交付要求

每个版本完成前必须具备：

- 明确的范围和不包含项。
- 可运行的用户闭环。
- 对应的 Schema 或迁移策略（如数据格式发生变化）。
- 自动化测试和浏览器验证。
- README、CHANGELOG 和版本计划同步。
- 一个可回退的 Git 发布检查点。

## 版本变更原则

- 修复错误且不改变数据格式：递增 patch 或预发布编号。
- 增加向后兼容的功能：递增 minor。
- 改变必填字段、字段含义或导入行为且无法自动兼容：递增 major，并提供迁移工具。
- 不因为内部重构单独提升角色 JSON 版本。
