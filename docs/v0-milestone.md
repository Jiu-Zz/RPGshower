# RPGshower v0 阶段目标

更新日期：2026-09-15

当前应用版本：`0.1.0`。本文件记录 v0 的阶段目标；版本路线和预发布节奏见 [版本实施计划](version-plan.md)，每次变更见 [CHANGELOG](../CHANGELOG.md)。

## 阶段目标

v0 要交付一个可靠的单角色工作台：用户可以加载示例角色或导入 JSON，修改常用字段或完整 JSON，在角色卡和档案视图中实时预览，最后导出一份可再次导入的数据文件。

本阶段不追求多角色管理、云端保存或具体规则计算。v0 的重点是验证以下完整闭环：

```text
示例角色或 JSON 文件
  -> 解析和校验
  -> 当前角色状态
  -> 基础表单或完整 JSON 编辑
  -> 角色卡或档案实时预览
  -> 导出 JSON
```

## v0 范围

### 必须完成

- 单角色 React 工作台和响应式页面布局。
- 角色卡视图：身份、基础资料、资源、属性、装备和技能。
- 档案视图：背景、外貌、性格、目标、人物关系、经历和备注。
- 基础表单：编辑姓名、称号、简介、基础资料、资源数值和属性值。
- 完整 JSON 编辑器：能够编辑整个角色对象并显式应用修改。
- JSON 文件导入和导出。
- Zod 运行时校验和 `schemaVersion` 兼容策略。
- JSON 语法错误和数据结构错误的清晰提示。
- 任何编辑或导入失败都不能破坏最后一份合法角色数据。
- 核心 Schema、兼容规则和导入导出往返测试。
- TypeScript、lint、测试、生产构建和桌面/移动端浏览器验证通过。
- README、数据示例和实现状态与代码一致。

### 明确不属于 v0

- 多角色资料库、搜索、筛选和角色分类。
- 浏览器自动保存、账号、数据库和跨设备同步。
- 使用普通表单增删装备、技能、标签、资源和属性；v0 通过完整 JSON 编辑器修改这些数据。
- 档案普通表单编辑；v0 通过完整 JSON 编辑器修改档案。
- React Router 和独立 URL 页面。
- 头像上传、图片画廊、PDF 或图片导出。
- 规则计算、骰点、战斗和会话管理。
- 多人协作、公开分享、插件和 AI 生成功能。

这些方向记录在 [长期产品路线图](long-term-roadmap.md)，不用于判断 v0 是否完成。

## 接续实施顺序

### 1. 整理数据操作边界

新增独立的导入导出模块，负责解析、校验、错误格式化和 JSON 序列化；将角色字段更新逻辑从 `App.tsx` 移入 reducer 或专用更新函数。完成后 `App.tsx` 主要负责顶层状态和页面组合。

### 2. 实现完整 JSON 编辑器

先使用原生 `textarea`，不急于引入 CodeMirror。编辑器至少提供：

- 从当前角色重新生成格式化 JSON。
- 应用 JSON 到当前角色。
- JSON 文本是否落后于当前角色的状态提示。
- 语法和 Schema 错误提示。
- 应用成功反馈。

只有解析和校验全部成功时才能替换当前角色。

### 3. 收紧约束和错误体验

明确资源是否允许负数、当前值是否允许超过最大值以及是否允许小数；让 Schema、基础表单和 JSON 编辑器遵守同一规则。导入与 JSON 编辑器应区分文件读取错误、JSON 语法错误、版本错误和字段错误。

### 4. v0 稳定和验收

补齐关键测试，验证空内容、长内容和移动端布局，更新 README 与设计状态。所有完成标准通过后，将版本状态标记为 v0 完成并创建干净的 Git 检查点。

## 完成标准

只有同时满足以下条件，才能宣布 v0 完成：

1. 用户能在全新页面上完成“导入或加载 -> 编辑 -> 两种视图预览 -> 导出 -> 再导入”的闭环。
2. 基础表单和 JSON 编辑器都不会产生未经 Schema 校验的角色状态。
3. 无效文件或编辑内容不会覆盖最后一份合法角色。
4. 导出的档案和 `extensions` 数据再次导入后保持一致。
5. 所有自动检查通过，桌面端与移动端没有内容重叠或无法操作的控件。
6. 文档准确说明当前能力、限制、数据版本和使用方法。
